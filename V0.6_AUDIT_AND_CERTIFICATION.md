# ALLI v0.6 Audit / Verification Record

## Architecture status

The implementation follows the locked v0.6 architecture rather than introducing a replacement architecture:

`understand → extract → validate → normalize/resolve → admission/lifecycle → SQLite + provenance → embeddings/index → structured/keyword/semantic/relationship/temporal retrieval → RRF/ranking → evidence grounding → Qwen → claim-safe answer`

The public production path is `MemoryEngine.remember()` / `MemoryEngine.recall()` and the CLI uses that same path.

## Root-cause fixes completed in the working tree

1. Removed the production CLI dependency on the legacy JSON memory source of truth.
2. Removed the production MemoryEngine dependency on the legacy retriever/store bridge.
3. Added canonical SQLite retrieval adapters directly on `SQLiteStore`.
4. Added `memory_type` to SQLite persistence and migration.
5. Added schema version recording and migration handling.
6. Changed SQLite `save()` from destructive replace-all behavior to non-destructive upsert.
7. Fixed entity foreign-key resolution for persisted memories.
8. Added per-candidate entity assignment in mixed/multi-entity statements.
9. Preserved mixed statement + question messages instead of dropping the statement.
10. Added episode persistence to the write path.
11. Persisted memory events through lifecycle operations.
12. Added embedding propagation to newly created operation objects when Ollama embeddings are available.
13. Tightened historical evidence validation so current active winners cannot satisfy historical queries.
14. Expanded query understanding for slang, learning queries, named people, reverse preference queries, unresolved pronouns, and self-identity.
15. Added isolated general-knowledge routing so personal memory is not injected into general answers.
16. Rebuilt the CLI around one MemoryEngine path.
17. Added reproducible `requirements.txt`.
18. Prevented runtime personal-memory/database artifacts from being shipped in the clean distribution.
19. Removed obsolete tests whose purpose was to require the old JSON synchronization architecture; replacement coverage targets the canonical SQLite architecture.

### Environment limitation

Real Ollama/Qwen and real embedding-model execution could not be certified in this environment because the Ollama Python package/service/model are unavailable here. The application is designed to use the real Ollama client when installed and configured.

## Certification decision

**S14 final certification/freeze: NOT CLAIMED.**

A true freeze requires the user's real development environment to run the real Ollama/Qwen model, the configured embedding model, adversarial natural-language tests, long-conversation persistence tests, and final performance measurements. This document intentionally does not fabricate those results.
